# MVP v0.16 — 交通・宿泊・ケータリング

原本6章Dに基づき、travel子フォルダに18番目のモジュールを追加する。

- 交通／宿泊／食事、手配名、対象役割ラベル・人数、移動手段、滞在先／場所、利用日・宿泊のチェックアウト日、食事内容、検討中／手配済み／利用完了／取消、総額・支払済み額・支払予定日／実施日、備考を記録する。
- 金額は手入力の税込総額。人数・金額は0以上の安全な整数。手配済み／利用完了には利用日と1人以上が必要。宿泊には利用日より後のチェックアウト日が必要。検討中は未定日を許容する。
- チェックアウト日だけの入力や逆順の日付は拒否。チェックアウト日は宿泊だけの予定に使い、他種別へ切り替えても入力済み値は保持する。
- 支払済み額は総額以下で、正額には支払日を必須にする。取消でも実支払を保持。取消以外の見込み額／未払額と、取消も含む支払済み額を区別する。分割支払履歴・返金・税務計算は扱わない。
- 利用日・宿泊チェックアウト・支払予定を固有IDで集約し、カレンダー／ダッシュボードから行へ戻る。利用完了で利用予定を完了、全額支払で支払予定を完了、取消は未完了予定を取消にする。
- CSV・専用JSON・全公演JSON・共有資料に接続。初期共有は人数・金額・場所・メモを含まず、選択時も既知項目だけ。バックアップは未知拡張を保持し、旧travel形式を無断置換しない。
- 予約実行・予約サイト接続・決算への自動加算を追加しない。個人名・連絡先・パスポート情報・個人ごとの健康情報を入力せず、役割と一般的な食事内容で記録する。

## 受入条件

- TRAVEL-01: 3種別・375pxの編集／保存／再読込、集計と取消後の支払保持、他モジュール保持。
- TRAVEL-02: 負数／小数／安全整数超過／超過支払／不正日付／状態／ID重複、手配済みの日程・人数不足、宿泊の日付不足／逆順、支払日不足を拒否し保存値を保持。
- TRAVEL-03: 利用／チェックアウト／支払予定のIDが重複せず、行リンクと期限超過、完了／取消の除外を確認。
- TRAVEL-04: CSV数式文字化、専用JSONの対象だけの復元と拡張保持、初期共有の私的項目除外と未知拡張除外。
- TRAVEL-05: 旧形式の無断置換なし。全入口の機微API／外部通信／攻撃文字列と明示出力、保存／印刷／上限試験を維持。

18モジュールの最小入口が揃うが、販売用単独配布・実機検証・保存隔離・クラウド同期は別工程。Notion正本は変更しない。
