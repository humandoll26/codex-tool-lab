# MVP v0.11 — モジュール単位のJSON受け渡し

各子フォルダの入口に「このモジュールのJSONを書き出す／取り込む」を追加。全公演JSONのバックアップは従来どおり保持する。

- 専用形式: format:theater-production-os-module、formatVersion:1、moduleId、document。documentはschemaVersion:1の共通公演情報・対象モジュールだけのmodules・対象モジュールに属するcalendarEventsを含む。project.documentsは空にする。共通公演情報の拡張は含まれ得るため、内容を確認して共有する。
- 未入力のモジュールは書き出さない。不正入力や破損保存では拒否。旧形式・拡張も妥当な保存契約の範囲で保持。
- 取込みはこの画面とmoduleIdが一致し、同じ公演IDの場合だけ許可。別公演に移植する機能ではない。通常の全公演JSONと専用形式を混同して取り込まない。
- 対象モジュールの入力・状態・日付と、そのモジュールの手動／逆算予定だけを置換する。共通マスター、documents、他モジュール、他の予定、逆算日数設定は現在値を保持。
- 現在のステージ・料金・席数で参照と金額を再検証し、不整合なら置換しない。現在の料金・会場などを使うため、元ファイル時点の表示と変わる場合がある。
- 置換は確認後だけ保存。取消・不正ファイル・保存競合で既存保存と画面入力を保持。保存容量不足では取り込んだ画面内容を保持し、JSON退避を案内する。
- 同期・チームの自動マージ・別公演移行・販売用ZIPは対象外。同じ公演IDを共有するには、先に全公演JSONを復元する。

## 受入条件

- PACK-01: 対象のデータと予定だけを書出し、他モジュールとdocumentsを含まない。選択モジュールの旧拡張を保持。
- PACK-02: 同じ公演への取込みで対象だけ置換、共通情報／他モジュール／他予定を保持。別公演・別モジュール・形式不正・参照不整合を拒否。
- PACK-03: 確認の取消・承認、容量不足・競合、不正入力の書出し拒否と未入力案内。全公演JSONの操作を維持。
- PACK-04: 15入口の手動出力、JSON不変と外部通信／自動ダウンロードなし。
