# MVP v0.4 — 受付・決算・パンフ・舞台進行

2026-10-02の継続実装指示に基づき、統合仕様5章・14章の次工程を実装する。既存7モジュール、保存キー、schemaVersion 1、逆算6予定を維持する。

- front-desk: 作業名・区分（配置／掲示／当日券／釣銭／備品／場内案内）・担当役割・期限・必要数／準備済み数・メモ・未着手／準備中／完了／不要。完了には必要数充足を要求。釣銭額は別の円フィールド。釣銭は費用に加算しない。受付用の準備一覧CSV、当日案内文。
- settlement: 実収入と支出の明細、区分・金額・受領／支払済み額・期限・メモ。未収／未払と現金収支を算出。売上−経費の収支と入金−支払の資金収支を区別する。実績販売枚数×現在価格の参考売上は実収入へ自動転記しない。税務・源泉徴収・会計連携は扱わない。釣銭は元手のため収入／費用へ自動加算しない。
- program: 掲載項目・種別・担当役割・原稿期限・本文・未依頼／依頼済み／受領／校正／校了。入稿予定日と公演マスターを参照した掲載テキスト、進行CSV。画像組版・PDF・個人情報なし。
- stage-operations: 作業名・日付・同日内の開始／終了時刻・部署・場所・必要人数・担当役割・メモ・予定／完了／中止。時刻順の進行表テキストとCSV。重複時間は部署と場所が同じ場合に注意として表示する（仕込みの並行進行は許容し保存を拒否しない）。既存の別ツールへの接続はその契約が決まるまで行わない。
- 各行の期限／日付をカレンダーへ集約。完了／不要／中止と入出金済みの明細は期限超過から除外。
- 不正入力は保存・出力を止め、前の保存を保持。金額・数量とその合計は安全な整数範囲。CSV数式無害化、JSON往復、375pxと外部送信なしを検証する。

## 受入条件

- EXT-01: 4単体入口、状態、OSの予定から作業行へ移動、旧7モジュールを保持。
- EXT-02: 受付数量・準備済み≦必要数、完了条件、釣銭額を保存・出力。不要は期限超過から除外。
- EXT-03: 決算の収支と資金収支、未収・未払、未決済合計を正確に算出。超過／小数／不正日付／整数範囲超過を拒否。現在価格の参考売上と混同しない。
- EXT-04: パンフ原稿・状態・入稿予定を保存、公演情報変更を掲載テキストへ反映。原稿締切を集約。
- EXT-05: 舞台進行の時刻順、終了≦開始の拒否、同部署・同場所の重複注意、完了／中止の期限除外。
- EXT-06: JSON往復・保存保護・375px編集、HTML風入力を実行せず、外部通信と自動ダウンロードなし。

原本転記は変更しない。本書の具体化はNotion反映候補。ログイン・個人連絡先・外部自動投稿・実機Safari・販売ライセンス・Google警告解除はこの実装の完了条件に含まない。
