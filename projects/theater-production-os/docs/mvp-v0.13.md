# MVP v0.13 — 項目を選べる共有用JSON資料

監査の共有範囲の課題に対応し、各モジュールで閲覧用JSON資料を作成する。既存の全公演/モジュールバックアップは復元・未知拡張保持の契約を維持する。

- 初期選択は公演名とモジュールの進行（状態・開始/期限・進捗）。劇団名、会場名、日時/席数、料金、作業データは個別に選択する。選択はブラウザへ保存せず、開くたび初期値へ戻す。
- 形式は `theater-production-os-share` / formatVersion:1。選択した共通情報と対象moduleだけを含む。schemaVersion付きの復元用documentは含めない。通常/専用JSON取込みでは共有資料との取り違えを案内して拒否する。
- 公演ID/更新日時、共通情報の未知拡張、documents、calendarEvents、他モジュール、アラート、モジュールの未知拡張は出さない。日時/料金を選んだ場合の参照用ステージID/料金IDと、作業データの行/参照IDは含む。
- 作業データは15モジュールの既知項目だけを明示的に選ぶ。各行、稽古の変更履歴、アーカイブの収支原稿も既知項目へ限定する。旧形式の作業データは出せず、進行状況の共有は可能。
- 作業データには金額・原稿・担当役割・メモ・保存原稿等が含まれる。文字列内の私的情報は自動判定/削除しない。公演名等を自由記述に書いた場合もその文字列は残るため、出力前に内容を確認する。
- プレビューを文字として表示し、選択変更ですぐ更新。出力ボタンは「共有用JSON資料を書き出す」。外部送信や自動DLはせず、画面・保存データを変更しない。保存不能/競合でも妥当な画面内の入力を使用できる。
- 不正/未入力/破損では共有を開始しない。資料も容量・深さ等の既存上限を適用する。

## 受入条件

- SHARE-01：初期出力に作業データ/金額/共通の追加項目が残らず、選択した項目だけが含まれる。
- SHARE-02：15モジュールの既知データを共有でき、行/履歴/保存原稿等の未知拡張と他モジュールを除外する。原本・既存バックアップは不変。
- SHARE-03：不正/未入力/旧形式/過大な資料を適切に案内。共有資料を全体/専用JSONへ誤取込みしても置換しない。
- SHARE-04：選択・プレビュー・出力・閉じる・再開で保存値/未保存入力/フォーカスを保持。選択の初期化、容量不足、保存競合を確認。
- SHARE-05：375pxと攻撃文字列、安全なプレビュー、明示出力だけのDL、外部通信なしを検証。

共有の最小化であり、匿名化・暗号化・同一オリジン隔離ではない。Notionへ反映する候補として記録し、原本転記は変更しない。
