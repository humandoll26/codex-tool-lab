# OS MVP実装範囲 — 2026-09-30

ユーザーから「MVP実装を継続してよい」と指示されたため、統合仕様14・15章に沿って次を実装する。初回TASKはPR未採用のためアーカイブせず、今回の追加範囲を本書で管理する。既存schemaVersion 1・保存キー・公演IDを維持し、初回データを移行なしで読めるようにする。

## 作業単位

1. 予算に続きflyer（チラシ掲載情報・校正）、distribution（部数・配布先）、publicity（投稿計画）、tickets（販売実績）を追加。各modules/<id>/に入口・固有モデル・画面・READMEを置く。
2. 各モジュール状態・開始日・期限を保存。未作成モジュールは未着手として表示。進捗率は別フィールドとして保持。
3. dashboard.htmlとcalendar.htmlをOS側へ追加。今日・月曜始まりの今週・期限超過・そろそろ開始を日本時間で判定し、モジュール・該当作業へ移動。
4. 最初のステージ日を基準に編集可能な逆算予定を生成。生成は明示操作、同じテンプレートIDは重複させず、既存予定の変更は確認後に行う。手動予定・別モジュールデータを保持。
5. JSON往復、入力エラー時の保存保護、モバイル、旧予算の回帰を検証。検証済みコードを作業ブランチとgh-pagesへpushする。

## モジュールの最小機能と判断

- flyer: 任意の紹介文・問い合わせ文・公式URL、印刷／納品予定日、原稿項目（名称・本文・校正状態）。公演タイトル・劇団・劇場・日時・料金はマスターから都度参照し、完成した掲載情報をテキストで書き出す。画像組版・PDF・個人情報は扱わない。
- distribution: 印刷総部数、配布先名・担当ラベル・方法・予定日・予定部数・配布済み部数・連絡状態。合計予定／配布済み・未配布・未割当を計算しCSV書出し。配布済み≤予定、予定合計≤印刷総部数。住所・個人の連絡先は扱わない。
- publicity: 投稿題名・媒体・予定日・原稿・素材メモ・下書き／確認済み／公開済み。外部への自動投稿なし。原稿テキストと計画CSVを書き出す。
- tickets: ステージ×料金区分ごとの実績販売枚数。残席・販売率・現行料金による参考売上。価格変更前の実収入や決済記録は扱わず、予算の想定販売とは別保存。実績合計≤販売可能席数。販売CSVを書き出す。
- 列挙した項目以外の旧拡張データはJSON値として保持。既に存在する未実装モジュールの異なるデータ形は編集前に互換性を検査し、無言で初期化しない。
- 予定は終日YYYY-MM-DD。追加するOS予定はdataVersion:1で識別して厳密に検証。旧版の任意calendarEventsは保持し、表示可能なものだけ表示する。UTC変換で日付をずらさない。
- CSVはUTF-8 BOM、引用符をエスケープし、数式として扱われる先頭文字を無害化する。

## 受入条件

- MVP-01: 5モジュールをOSと単体入口から利用し、同じ公演・状態を保持する。
- MVP-02: チラシ掲載情報はマスター変更を反映し、原稿・校正・印刷予定を保存・出力できる。
- MVP-03: 配布の残部と合計を正確に算出、超過・負数・小数・不正日付は保存しない。
- MVP-04: 投稿を作成・編集・状態変更し、日付から予定へ集約・原稿出力できる。
- MVP-05: 実績販売と想定販売を別に保存し、残席・参考売上・販売率を算出する。
- MVP-06: 今日・今週・月間・モジュールフィルタ・期限超過・そろそろ開始が日本時間で動作する。
- MVP-07: 逆算日数の変更、重複防止、変更確認・取消、手動予定保持、公演日変更の警告が動作する。
- MVP-08: 予定から該当モジュールと作業行へ移動し、未実装の予定は壊れたリンクにしない。
- MVP-09: JSON往復・旧phase-1保存データ・未知拡張を保持し、不正データや保存失敗で既存保存を壊さない。
- MVP-10: 375px幅で入力・移動・カレンダー表示ができ、HTML風入力をテキストとして扱う。

Notion原本は変更せず、採用後に以上の具体化を反映する候補として残す。ログイン・共同編集・個人情報・決済・販売用ライセンスの実装は含まない。
