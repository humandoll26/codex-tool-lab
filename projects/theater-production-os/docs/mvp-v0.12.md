# MVP v0.12 — 取込み上限と印刷用資料

原本12章の受付用資料・タイムスケジュールPDFを、ブラウザの印刷用プレビューと「印刷・PDF保存」で具体化する。サーバーや外部PDFライブラリを使わず、利用者が印刷画面でプリンター/PDFを選ぶ。iPhoneでのPDF保存操作はブラウザ・OSに従う。

- 受付：公演名・劇団・会場・全ステージ・料金、釣銭元手、案内文、準備作業の区分・担当役割・期限・必要/準備数・状態・メモを表示する。
- 舞台：公演基本情報、日付/開始順の作業、終了・部署・場所・人数・担当役割・状態・メモを表示する。取消も表示し、重複注意を付ける。既存の入力を変更しない。
- 印刷用表示は現在の妥当な画面データから生成。入力不正・破損保存では開始しない。保存容量不足/競合でも画面内の妥当な内容を出せる。
- プレビュー中は編集画面を隠し、戻る操作で表示・フォーカスを復元。印刷では操作ボタンを除き、白地/A4/改ページを考慮する。長文・HTML文字列は文字として表示する。自動印刷・ダウンロード・外部送信を行わない。

監査のJSON可用性改善も同時に行う。

- JSON/モジュールJSONはUTF-8で2MiBまで。ファイルのsizeを読込み前に確認し、文字列もJSON.parse前に確認する。
- データ構造は深さ64、合計50,000値まで。明示スタックで検証し、循環参照と非JSON値は拒否。数値の有限値確認を維持する。
- 配列は1,000件まで、共通ステージと料金区分の組合せは2,000件まで。過大な入力でDOM生成や繰返し処理が膨らむのを抑える。
- 舞台の時間重複注意は先頭100件までとし、100件到達時に表示上限を案内する。
- 上限超過では取込み/保存を拒否し、元データと入力を保持。保存済みの上限超過JSONも無言で変更せず、元の文字列を復旧出力できる。schemaVersionと保存キーを維持し、上限内の未知拡張は保持する。
- モジュール形式の包み込みにも同じ上限を適用する。プレビュー/印刷/保存失敗により他の情報を捨てない。同一オリジン隔離と共有用JSONの項目選択は別課題として残す。

## 受入条件

- LIMIT-01：UTF-8容量の境界、深さ/値数/配列長の境界、循環・非有限数値を検証し、過大な元保存値を保持する。
- LIMIT-02：ファイル上限を全体/モジュールに適用。拒否で確認ダイアログも置換も発生せず、正常JSONは従来通り確認付きで取り込める。
- LIMIT-03：過大なステージ×料金区分を拒否。上限内の未知拡張・サンプル・既存モジュールJSONを保持する。
- PRINT-01：受付資料と舞台進行表に上記の内容が出る。並び順・取消/完了・重複注意を維持し、入力が変わらない。
- PRINT-02：開始/終了/印刷取消で入力・保存値とフォーカスを保持。不正入力では拒否。明示操作だけでwindow.printを呼ぶ。
- PRINT-03：長文/攻撃文字列の安全表示、375px表示、印刷CSS/A4 PDFを検証し、外部通信・自動ダウンロードを起こさない。

上限値と印刷UIは小規模劇団向けMVPの実装判断。Notion反映候補として記録し、原本転記は変更しない。以前の大きなバックアップは元ファイルを保管し、上限内へ分割/整理して取り込む。
