# 予算・料金・損益分岐モジュール

- 状態: usable（phase-1 v0.1の受入条件を検証済み）
- [OSのSPEC](../../SPEC.md) / [TASK](../../TASK.md) / [共通データ契約](../../docs/data-contract-v0.1.md)
- 単体入口: `index.html`。OS入口からも同じ公演IDで起動できます。

公演マスターの席数・料金を参照し、固定費・1人当たり変動費・想定販売枚数から売上・費用・収支・販売率を計算します。
基準料金による損益分岐人数は参考値で、複数料金の販売構成によって実際の損益分岐は変わります。
想定販売は販売実績や予約者データとは区別しています。

## 起動・検証

プロジェクト直下で `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、サーバーの `/modules/budget/index.html` をブラウザで開きます。
公演が未登録なら、この画面の公演情報編集から作成できます。

プロジェクト直下の `npm test` と `npm run test:browser` で計算・保存・画面を検証します。
詳しい依存導入・対応ブラウザ・保存の制約は [OSのREADME](../../README.md)、結果は [検証記録](../../artifacts/verification.md) にあります。

## モジュールの境界

画面の入口はこのフォルダに置き、固有の入力画面は `editor.js`、計算は `calculator.js` に配置します。公演データ・共通検証・保存・OSの画面構築は `shared/` を参照します。
公演マスターを複製して保存せず、`project.modules.budget.data` に予算固有の入力だけを保存します。
同じHTTP originでOSと単体入口が同じデータを使います。切り売り用ZIP等の独立配布方式は今回の対象外です。

予算をテキスト／CSVで書き出し、プレビューをコピーできます。出力は想定販売の試算です。基準料金の前提と黒字化不可／収容人数超過の説明を含めます。不正入力や予算未作成では出力しません。CSVは入力文字列の数式を無害化し、計算した負の数値は数値のまま出力します。
