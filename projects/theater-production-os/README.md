## 起動

実行時のnpm依存・ビルド・外部API・秘密情報は不要です。Python 3があれば次で起動できます。

```bash
cd /workspace/codex-tool-lab/projects/theater-production-os
python3 -m http.server 8765 --bind 127.0.0.1
```

ブラウザで、起動したHTTPサーバーの `/index.html` を開きます。
各モジュールの単体入口は `/modules/<id>/index.html` です。IDはbudget、flyer、distribution、publicity、tickets、rehearsal、submissions、front-desk、settlement、program、stage-operations、venue、rights、show-day、archive、contracts、funding。
ダッシュボードは `/dashboard.html`、カレンダーは `/calendar.html` です。OSのナビから移動できます。
上記パスはサーバーをこのプロジェクトで起動した場合です。親フォルダから配信する場合はプロジェクトまでのパスを付けてください。
`file://` での直接起動は対応しません。ES Modulesと同じoriginの保存領域を利用します。
Cloudのこのチャットではlocalhostのプレビューリンクは提供していません。起動・操作はChromiumで検証しました。

1. 公演タイトル、日本時間のステージ日時、販売可能席数、料金区分を入力します。
2. 「予算モジュールを開く」で移動し、固定費・1人当たり変動費・ステージ／料金別の想定販売枚数を入力します。
3. 基準料金を選択すると、全員がその料金で購入する場合の損益分岐人数が表示されます。
4. チラシ・配布・SNS・販売進捗も制作モジュールから開けます。それぞれの状態・開始日・期限を入力できます。
5. カレンダーで手動予定を追加するか、本番からの逆算予定を生成します。日数は編集可能です。
6. ダッシュボードで今日・今週・期限超過・そろそろ開始を確認します。
7. 稽古で日時・場所・連絡事項を入力し、必要に応じ「予定変更を記録」を押します。提出物で期限と状態、提出済みの日付を管理できます。
8. 受付の必要数と準備状況、パンフ原稿と期限、舞台の同日内タイムラインを管理します。決算は実収入・経費・入出金済み額を入力し、未収／未払を確認できます。
9. 劇場候補の名称を公演情報へ明示反映し、作品の上演時間と権利確認、当日の受付・物販・トラブル記録を管理します。
10. 上部の「作業モジュール」で直接切り替えられます。ダッシュボードは今日／今週と期限超過を先に表示し、一覧を検索・状態で絞れます。月間カレンダーの日付でその日の予定を選べます。
11. 予算・原稿・進行表のプレビューからコピーでき、予算もテキストとCSVを書き出せます。コピー不可の場合は文字選択と手動コピーを案内します。
12. カレンダーの表示月・日付・モジュールを選ぶと、その予定をICS／CSVに書き出せます。ICSは手元のカレンダーアプリでファイルを取り込むための形式です。自動同期ではありません。
13. 決算で「収支・実績レポート」をプレビュー・コピー・テキスト／CSVに書き出せます。予算との差、未収／未払、実績枚数、物販参考値を区別して集計します。
14. アーカイブで資料の保存場所と来場者数・反省／引継ぎを記録します。「現在の収支原稿をアーカイブに保存」で、保存時点のレポートを残せます。
15. 各入口の「このモジュールのJSON」で、同じ公演の対象モジュールだけを受け渡せます。共通公演情報も含みます。取込みは対象の入力と予定だけを置換し、現在の公演マスター・他モジュールを保持します。別端末では先に全公演JSONを復元してください。
16. 妥当な入力は自動保存されます。「JSONを書き出す」でバックアップできます。
17. 受付・舞台進行の「印刷用プレビュー」から「印刷・PDF保存」を押し、ブラウザの印刷画面でプリンターやPDFを選べます。「編集画面へ戻る」で入力を保持して戻れます。iPhoneの保存方法はブラウザ/OSの印刷・共有メニューに従います。
18. 各モジュールの「共有用資料を作成」で、相手に渡す項目を選んでJSONをプレビュー・書出しできます。初期状態は公演名と進行状況だけです。作業データ・料金等は自分で選び、原稿やメモの内容も確認してください。選択は次に開くと初期値へ戻ります。閲覧用資料なので、復元には従来のバックアップJSONを使います。

19. 契約・支払いで契約状態・金額・請求書受領・支払予定／実施日を記録できます。支払予定はカレンダーへ表示します。金額は決算へ自動転記しません。

20. 助成金・協賛・広告で申請・報告・入稿の締切と入金を記録できます。採択・確定額と実際の入金額を区別し、予定から案件へ戻れます。

単体入口でも「公演情報を作成・編集する」から同じ情報を編集できます。
iPhone等では画面上の「サンプル公演を試す」から、17モジュールの架空データを読み込めます。現在の公演を置き換える確認が出ます。
初期データは空です。[架空の試算サンプル](artifacts/sample-project.json)をJSON取込みで読み込めます。
現行公演を置き換える確認が出るので、本番データを使う場合は先に書き出してください。

## 保存・エラー・復元

- 保存キーは `codex-tool-lab:theater-production-os:v1`。他ツールの保存データには触れません。
- 不正な入力は画面に残り、エラーを表示します。最後に妥当な状態で保存したデータを壊しません。
- 不正な入力中は、JSON書出しと画面間の移動を止めます。同じ画面内で公演情報と予算を修正できます。
- 保存に失敗した場合は警告を表示し、画面内の妥当なデータをJSONで書き出せます。別画面への移動はデータ喪失を避けるため止めます。
- 保存データが破損している場合は編集・上書きを止め、元のデータを書き出せます。正常なJSONの取込みか確認付き全消去で復旧できます。
- JSON取込みは版・構造・ID・参照・値・計算を検証し、置換の確認後だけ反映します。未実装モジュールや拡張フィールドも保持します。
- 全公演/モジュールJSONはUTF-8で2MiB、深さ64、合計50,000値、各配列1,000件までです。ステージ×料金区分は2,000組まで。上限超過で既存保存を変更しません。保存済みの過大データは元のJSONを復旧出力できます。書出しは整形後に大きすぎる場合、空白を省いたJSONにします。
- `projectId` が保存済み公演と一致しないURLでは編集せず、公演の作成・編集へ案内します。

## テスト

Node.js 24以上で計算・入力・保存のテストを実行できます。

```bash
cd /workspace/codex-tool-lab/projects/theater-production-os
npm test
```

ブラウザテスト用の依存はこのフォルダ内だけに配置します。
Playwrightは実行時依存ではなく、操作・保存・遷移の検証用です。版はlockfileで固定しています。

```bash
npm ci --ignore-scripts
npm run test:browser
```

ブラウザテストは `/usr/bin/chromium` を使用し、専用のHTTPサーバーと一時ブラウザコンテキストを自動で起動・終了します。
別の場所にChromiumがある場合は `CHROMIUM_PATH=/absolute/path/to/chromium npm run test:browser` と指定します。
現在の検証環境はNode.js 24.19.0、Chromium 151.0.7922.173、Python 3.12.14です。

## 対応範囲・制約

- Chromium 151でデスクトップと375px幅を検証。Firefox・Safari・実機スマートフォンは未検証です。
- 1公演・1会場・複数ステージ・複数料金区分。金額は税込総額の円、日時は日本時間。
- データは端末・ブラウザ・HTTP originごとです。URLのホスト・ポートを変えると別の保存領域になります。
- JSONを保管しないままブラウザのデータを消すと、公演を復元できません。
- 他タブなどによる保存値の変更を検知すると、自動保存と移動を止めます。画面内の入力をJSONへ退避し、確認付きで保存データを読み直せます。自動マージ・排他ロックではないため、通常は1つのタブで編集してください。
- アクセス制御・暗号化は実装していません。予約者の氏名・連絡先等の個人情報を入力しないでください。
- 同じoriginの別パスのサイトも保存領域を共有します。GitHub Pagesの別リポジトリのサブフォルダだけでは隔離できません。モジュールJSONにも共通情報の追加項目が残るため、共有前に内容を確認してください。[監査記録](artifacts/manual-security-audit.md)。
- 共有用資料は選んだ共通情報と対象モジュールの既知項目だけを出し、未知の追加項目・他モジュール・資料/予定を除きます。作業データの文章内の私的情報は自動削除せず、暗号化・匿名化もしません。バックアップの拡張保持は従来どおりです。
- 予約者管理・決済・税務計算・複数公演・クラウド同期は対象外です。
- OS MVPには17モジュール、カレンダー、逆算予定、今日／今週とダッシュボードを含みます。12工程＋稽古・提出物・アーカイブの最小機能を接続しています。交通・宿泊等は後続です。
- カレンダーは日本時間で管理し、時刻のある予定と終日予定を区別します。今週は月曜〜日曜、そろそろ開始は今後7日以内の未着手モジュール。不要・完了モジュールは期限超過アラートから除きます。
- 逆算予定は最初のステージ日を基準に生成。再生成は確認後に行い、手動予定・状態・編集した名称は保持します。公演日が変わったら警告を表示し、勝手に予定を変更しません。
- チラシは文字原稿、SNSは計画管理です。自動投稿・画像組版は未対応。受付資料/舞台進行表のPDFはブラウザ印刷で作成します。販売の参考売上は現行料金によるため、過去の実収入を表しません。
- 単体起動でも予算は `shared/` を参照します。今回の成果物はOS内の独立した入口です。販売用の配布物・ライセンス・課金方式は未定義です。

Notion正本は変更していません。実装上の判断はSPEC末尾に記録しています。


## GitHub Pagesの更新

配信元はgh-pages / (root)。API接続は不要です。コミット済みのアプリを次で配信ブランチへ反映できます。

```bash
python3 scripts/publish-pages.py --push
```

未コミットのプロジェクト変更がある場合は実行を止めます。アプリ用HTML/JS/CSSとsamplesのJSONだけを配信し、テスト・文書・依存は配信しません。
GitHub上のPages設定は別途必要です。push成功だけで公開サイトの配信完了とは判断しません。
